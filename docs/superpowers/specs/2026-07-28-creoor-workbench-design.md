# Creoor 服装设计 Agent 无限画布工作台设计

## 1. 目标

Creoor 首先服务服装设计师与服装品牌团队。首轮原型聚焦项目工作台，通过 Agent 对话理解、询问和澄清用户意图，并以无限画布承载图片、文字、笔迹及生成结果。

首轮原型放在仓库根目录的独立 `creoor/` 前端项目中。后端请求和数据全部使用 Mock，优先验证视觉、交互、画布编辑和 Agent 上下文体验。主页不在首轮精细设计范围内，只保留必要的返回入口。

支持桌面 Web 与 iPad 横屏。Apple Pencil 首轮完成事件与输入模式兼容，压感、倾角等高级笔刷表现作为渐进增强。

### 1.1 首轮主角色与验证目标

首轮主角色是独立工作的服装设计师；品牌创意团队成员作为次级评审者，但首轮不验证多人实时协作、审批或权限管理。

原型验证以下假设：

- 设计师能理解 Agent 只读取显式加入当前会话的对象，而不是自动读取整张画布。
- 设计师能在不离开画布的情况下完成素材导入、澄清、派生、比较、保存和导出。
- 设计师能通过图片类型驱动的操作菜单找到适用的服装专业能力，并理解操作的适用范围。
- 可吸附、可悬浮面板在桌面和 iPad 横屏下都不会妨碍核心创作。

Mock 原型只验证交互、信息架构和上下文表达，不验证真实 AI 输出质量、识别准确率或生成速度。

### 1.2 黄金路径

首轮必须完整支持两条端到端路径：

1. **服装变体路径**：导入服装图片 → Mock 离线识别 → 查看或修正标签 → 添加到 Agent → Agent 澄清 → 执行换面料或换纹样 → 派生结果放在原图旁 → 比较 → 保存到我的图库 → 导出。
2. **批注引用路径**：使用画笔或套索标注局部 → 生成冻结的批注截图 → 在 Agent 输入框通过 `@` 精确引用 → 刷新后恢复消息、引用和截图。

除这两条路径外的首轮功能必须在范围表中标为“可用”“仅视觉”或“排除”，不能只出现入口而没有行为。

## 2. 核心原则

- 画布优先：工作台背景即无限画布，功能面板悬浮于画布之上。
- Agent 可见：Agent 默认位于右侧，但与其他主面板一样可以拖动、吸附、悬浮与收起。
- 上下文显式：Agent 不自动读取整张画布，用户必须显式添加图片、对象或选区。
- 服装专业化：图片识别与操作优先覆盖服装、面料、纹样、模特和商品视觉流程。
- 视觉统一：所有组件通过主题 Token 引用视觉值，不允许散落未经批准的颜色、字号、阴影或层级数值。
- 跨输入设备：鼠标、键盘、触控和 Apple Pencil 使用同一行为模型，并针对触控目标和手势冲突做适配。
- 非破坏性：图片操作默认创建派生节点并保留原图；来源关系、参数和适用范围可追溯。
- 本地透明：原型不会把用户素材发送到网络；“私有”仅表示当前浏览器配置文件中的本地数据。

## 3. 工作台空间结构

默认布局为：

- 用户与项目卡片位于左上角。
- 创作工具栏紧贴左侧屏幕边缘。
- 小地图、网格吸附、图层、快捷键和缩放工具位于左下角。
- Agent 对话面板位于右侧。
- 中间区域保持为尽可能完整的无限画布。

默认结构借鉴 Miora 的全屏点阵画布、轻量悬浮层和边缘控制，但将 Agent 的信息重心放在右侧。

## 4. 可编排主面板

以下四个区域统一使用 `DockablePanel` 行为模型：

1. 用户与项目卡片。
2. 创作工具栏。
3. 画布辅助工具。
4. Agent 面板。

面板状态由四个正交维度组成，禁止压缩成一个互斥 `mode`：

```ts
type PanelPlacement =
  | { kind: "docked"; edge: "top" | "right" | "bottom" | "left"; offset: number; size: number }
  | { kind: "floating"; x: number; y: number; width: number; height: number };

type PanelInteraction =
  | { kind: "idle" }
  | { kind: "dragging"; origin: PanelPlacement }
  | { kind: "resizing"; origin: PanelPlacement; edge: string };

type PanelState = {
  placement: PanelPlacement;
  visibility: "expanded" | "collapsed" | "peek";
  persistence: "auto" | "pinned";
  interaction: PanelInteraction;
};
```

`dragging`、`resizing` 和 `peek` 是瞬时状态，不持久化。序列化只保存 `placement`、正常 `visibility` 与 `persistence`；`peek` 按其来源恢复为 `collapsed`，`interaction` 一律恢复为 `idle`。所有位置与尺寸在写入前完成 viewport clamp。

交互规则：

- 面板可以拖至任意位置，靠近上下左右边缘时显示吸附预览。
- 面板吸附后与屏幕边缘融合，减少外侧圆角和阴影，强化内侧边界。
- 面板悬浮时使用完整圆角、柔和阴影与适量背景模糊。
- 临时展开的面板在点击画布空白后恢复收起；固定展开面板不受影响。
- 面板自动避让其他已吸附面板，不允许完全重叠。
- Agent 面板支持拖拽调整宽度。
- iPad 使用明确的拖动抓手，避免与画布平移和 Apple Pencil 绘制冲突。
- 提供恢复默认布局。

左上角的 `UserProjectPanel` 同时承担项目入口。它显示当前项目、最后产出缩略图和最近项目，并支持新建、重命名、切换和删除；项目过多时折叠为可搜索列表。项目卡片优先使用最近一次成功生成或图片操作的可见派生结果缩略图，尚无派生结果时回退到最近导入图片，再回退到主题占位；删除当前封面后按同一规则重新计算，不复制原始 Blob。所有破坏性操作必须先展示影响范围并允许取消。

必须支持以下状态转移：

- `docked + collapsed → peek → 点击画布空白/Escape → docked + collapsed`。
- `floating + collapsed → peek → 点击画布空白/Escape → floating + collapsed`。
- 任意正常状态 → dragging → 吸附成功或恢复原 placement。
- `pinned` 面板不因画布空白点击关闭。
- 拖动取消、`pointercancel`、窗口失焦和越界必须恢复到拖动前状态。
- 刷新后不恢复 `peek`、`dragging` 或 `resizing`。

布局分别保存桌面与 iPad 两套设备配置。同一设备默认跨项目复用，项目允许保存覆盖配置。

布局 profile 主要由可用 viewport 尺寸和用户显式选择决定，不以单个 `(pointer: coarse)` 结果识别设备。`any-pointer`、`any-hover` 和最近输入 modality 只影响触控目标和动效触发。iPad 外接鼠标、触摸 Windows、分屏、旋转和浏览器缩放不得覆盖另一套已保存布局。支持 `env(safe-area-inset-*)`、动态浏览器工具栏和软键盘；竖屏或过窄窗口显示可继续使用的单面板模式并提示横屏体验更完整。

## 5. 工具栏与二级工具层

工具栏支持紧凑与展开两种密度：

- 紧凑状态只显示图标。
- 展开状态显示动态图标、中文名称和键盘快捷键。

点击具体工具后打开独立的 DOM 二级浮层。例如画笔工具显示粗细、颜色、透明度和预设。二级浮层默认锚定当前工具，也可以拖离并成为独立浮动面板。

动态图标优先使用 MIT 许可的 Lucide Animated，缺失图标回退至同风格 Lucide。图标默认静态，仅在悬停、触碰、激活或状态变化时播放一次。生成、上传、语音录制等持续状态允许循环。系统开启 reduced-motion 时退化为静态或必要淡入淡出。

## 6. 主题与视觉规范

主题使用四层引用链：

`基础 Token → 语义 Token → 组件 Token → 状态/动效 Token`

### 6.1 基础 Token

包括品牌色、灰阶、字体族、字重、字号、行高、间距、尺寸、圆角、边框宽度、阴影、模糊、透明度、层级、动画时长和曲线。

字体契约：

- 中文统一使用仓库内自托管的 `Noto Sans SC Variable` WOFF2；英文和数字统一使用仓库内自托管的 `Inter Variable` WOFF2。
- 字体文件与 OFL 许可一同提交，不使用系统字体作为视觉基线，也不在运行时请求 CDN。
- CSS fallback 仅用于字体加载失败时维持可用性；视觉回归必须等待 `document.fonts.ready`，并断言两种字体均已加载，否则测试直接失败且不得生成新基线。
- UI 正文默认 14px，辅助文字 12px，按钮与工具项 13–14px，面板标题 16px。
- 桌面触控目标不小于 36px，iPad 触控目标不小于 44px。

首轮浅色主题采用暖中性画布、白色实体面板和橙色交互强调：

| 角色 | 基准值 |
| --- | --- |
| Canvas background | `#F5F4F0` |
| Elevated surface | `#FFFFFF` |
| Floating translucent surface | `rgba(255, 255, 255, 0.94)` |
| Primary text | `#191916` |
| Secondary text | `#6E6D67` |
| Subtle border | `#DEDCD5` |
| Brand/action/selection | `#F36B2B` |
| Focus ring | `#315CF4` |
| Danger | `#C83B37` |

基础圆角为 10px，面板圆角为 18px，胶囊为 999px。浮动面板使用两级阴影，吸附面板只保留内侧弱阴影。实际组件不得直接引用表中原始值，必须经过 Token 引用链。

Miora 只作为空间结构参考：允许借鉴全屏点阵画布、白色悬浮面板、贴边工具栏和轻量边缘控件；不复制其品牌、Logo、内容或具体组件样式。正式视觉验收以 Creoor 固定数据和截图基线为准。

### 6.2 语义 Token

示例包括：

- `surface.canvas`
- `surface.floating`
- `text.primary`
- `text.muted`
- `border.subtle`
- `border.focus`
- `action.primary`
- `status.warning`

### 6.3 组件 Token

示例包括：

- `toolbar.docked.background`
- `agent.floating.shadow`
- `imageMenu.radius`
- `composer.reference.selectedBorder`

### 6.4 状态与动效 Token

覆盖 `docked`、`floating`、`collapsed`、`expanded`、`active`、`disabled`、`dragging` 和 `generating`。

视觉规则：

- 画布背景保持低对比度，点阵和网格不与作品争夺注意力。
- 是否显示背景、边框、阴影和模糊由组件 Token 控制。
- 首轮实现浅色主题，并为深色和高对比度主题保留完整语义结构。
- 面板展开时长建议为 180–240ms，吸附使用轻微弹性反馈。
- reduced-motion 关闭位移和弹性，仅保留必要淡入淡出。
- 颜色必须满足可读性要求，选中、错误和生成状态不能只依赖颜色表达。
- 开发环境检查未经批准的颜色值、字号、阴影和 `z-index`，避免视觉常量散落。
- 检查必须覆盖 CSS、TS、TSX、inline style 和 Konva `fill/stroke`；组件 Token 必须引用语义 Token，语义 Token 必须引用基础 Token，未定义 Token 在开发与 CI 中直接失败。

## 7. 无限画布技术架构

使用 React、Konva.js 与 `react-konva` 的混合架构：

- Konva 负责图片、文字、笔迹、选区、Transformer、辅助线、框选和导出。
- React DOM 负责四个主面板、图片操作菜单、Agent、二级工具层、表单、Tooltip 和弹窗。
- 统一坐标转换服务维护画布坐标与屏幕坐标的映射，使 DOM 浮层可以跟随画布节点。
- React 状态是文档和图层数据的唯一事实来源，Konva 负责渲染和交互，不直接作为持久化数据源。

状态必须拆分为：

- `ProjectDocument`：画布节点树、生成器参数、派生关系和项目资产引用。
- `HistoryState<ProjectDocument>`：只记录可撤销画布命令。
- `WorkspaceState`：当前项目、当前工具、面板布局和设备 profile。
- `SessionState`：会话、消息和显式引用。
- `EphemeralInteractionState`：hover、选择框、拖动预览、吸附线和活动 pointer；不持久化、不进入 undo。

图片、缩略图和批注截图不进入文档快照；它们通过稳定 `assetId` 引用资产存储。

### 7.0 坐标与 DOM Overlay 契约

坐标类型不得混用：

- `CanvasPoint`：持久化的无限画布坐标。
- `StageLocalPoint`：相对 Stage 容器的 CSS 像素坐标。
- `ClientPoint`：浏览器 viewport 坐标。
- `OverlayPoint`：相对统一 overlay portal root 的坐标。

转换必须包含 Stage viewport transform、容器 `getBoundingClientRect()`、节点 absolute transform 和节点 `getClientRect()`。DOM 菜单与表单统一挂载到 Stage 外同一 overlay root，并响应 ResizeObserver、VisualViewport、safe-area、软键盘、滚动和窗口 resize。0.1×、1×、4×缩放以及旋转节点下，锚点误差不得超过 2 CSS px。

### 7.1 Konva 渲染层

保持 3–4 个固定渲染层：

1. 背景层：点阵、网格和画布背景。
2. 内容层：图片、文字、笔迹和用户逻辑图层。
3. 交互层：选框、Transformer、吸附线和拖拽预览。
4. 临时层：正在绘制或高频拖动的对象；交互结束后归还内容层。

用户图层不与 Konva Layer 一一对应。逻辑图层使用无环树结构：每个节点拥有稳定 ID、`parentId` 和有序 `childIds`。隐藏与锁定从父级继承；group/ungroup 后必须保持世界坐标、旋转和缩放；非法循环与重复父级由 reducer 拒绝。

逻辑图层树同时作为 Canvas 的 DOM accessibility mirror。它为每个可见对象提供名称、类型、选择状态和基础操作，支持键盘选择、删除、微移、重命名、隐藏、锁定和层级调整。隐藏对象不进入可聚焦顺序；视觉顺序改变后 DOM 顺序同步。

### 7.2 吸附

支持：

- 网格吸附。
- 画布边缘吸附。
- 对象边缘和中心点吸附。
- 水平与垂直参考线。
- 旋转角度吸附。
- 吸附开关、网格尺寸和吸附强度。

吸附阈值按屏幕像素计算，避免随画布缩放改变手感。

### 7.3 输入设备

- 鼠标支持滚轮缩放、拖动、框选和快捷键；触控板的 `ctrlKey` pinch-wheel 与普通 wheel 都执行以指针为中心的缩放。
- iPad 支持双指缩放和平移。原生 Pointer Events 统一拥有手势序列，Konva 只提供命中信息和渲染，不启动第二套触控状态机。
- Apple Pencil 通过原生 Pointer Events 捕获压力、倾角和笔型信息，再交给 Konva 渲染。
- 画笔首轮使用 `Konva.Line` 保存可编辑矢量笔迹；大量笔迹时可以合并到离屏 Canvas。

输入由单一 `InteractionController` 仲裁，同一 pointer sequence 只能归属于一个行为：

| 当前工具 | 鼠标/触控笔 | 单指 | 双指 | Apple Pencil |
| --- | --- | --- | --- | --- |
| 选择 | 点击选择；拖空白框选；拖对象移动 | 点击选择；拖对象移动 | 平移与缩放 | 选择或移动，不绘制 |
| 手形 | 左键、空格拖动或中键平移 | 平移 | 平移与缩放 | 平移，不绘制 |
| 画笔 | 按下绘制 | 平移画布 | 平移与缩放 | 按压力采样绘制 |
| 套索/批注 | 绘制选区或批注 | 平移画布 | 平移与缩放 | 绘制选区或批注 |

控制器必须处理 pointer capture、`pointercancel`、窗口失焦、第二触点加入或离开、Safari passive listener、`touch-action` 和滚动穿透。Wheel 需要归一化 pixel/line/page `deltaMode`，以有界指数曲线缩放并保持指针下画布点不漂移；只有画布拥有该 wheel 序列时才 `preventDefault()`。空格拖动和中键拖动均平移。输入框、下拉菜单和可滚动面板内的事件不得触发画布快捷键、缩放或手势，同一事件不得被原生边界与 Konva 重复处理。

### 7.4 导入、创作与导出

- 图片导入支持 PNG、JPEG、WebP 和 iPad 常见 HEIC/HEIF 的“可解码则导入、不可解码则给出转换提示”策略；保留 EXIF 方向。
- 文字工具可以创建、编辑和提交文字节点。
- 画笔、套索和批注笔迹在 pointer sequence 结束时作为一个 history transaction 提交；300 个 move 事件只产生一个 undo 条目。
- Canvas 导出服务明确 crop、pixelRatio、背景、包含的逻辑图层和最大像素限制；Transformer、参考线和 DOM 浮层不进入导出。
- Mock 公共图库使用同源本地资源；任何无 CORS 许可的网络图片在进入 Stage 前拒绝或降级，不能污染整个 Canvas。
- 支持导出选区 PNG 和整个作品区域 PNG。选区导出使用当前选区的世界坐标包围盒；作品区域导出使用所有可见内容节点包围盒的并集并增加 32 canvas-unit 留白，不是当前 viewport 截图。
- 锁定但可见的节点进入导出；隐藏节点、Transformer、参考线、选择框、DOM 浮层和面板不进入导出。两种模式均支持 `pixelRatio` 1/2、透明或画布背景；空选区/空作品时禁用对应操作。超过最大像素限制或导出失败时在原位置反馈，不改变文档且不创建空文件。

## 8. 图片识别与智能操作

每张图片导入后进行离线视觉识别，并允许同时命中多个标签。

首轮不运行真实视觉模型，而是由 Mock 服务返回确定标签。界面必须明确标注“演示识别”，不能暗示已完成真实设备端模型推理。识别状态包括 `queued`、`recognizing`、`completed`、`empty` 和 `failed`。

每个标签包含来源 `mock | user`、可选置信度和稳定 ID。用户可以查看、添加、删除或修正标签；操作菜单在标签变化后立即重新计算。用户修正优先于 Mock 结果。

### 8.1 标签体系

- 内容主体：模特、服装、鞋履、箱包、配饰、面料、纹样。
- 图像形态：写真、商品图、线稿、款式图、平铺图、随手拍、局部细节、拼贴板。
- 视觉属性：正面、侧面、背面、棚拍、户外、纯色、印花、人物、静物、完整、局部。
- 质量状态：低清、背景杂乱、透视变形、光线不均、遮挡、文字水印。

### 8.2 操作体系

通用操作包括高清、裁剪、扩图、去背景、擦除、改字、拆分、矢量化、调整视角、反推提示词、重新生成和添加到对话。

服装专业操作包括换款、改版型、换面料、换纹样、改配色、系列延展、虚拟试穿、生成正侧背、款式图和工艺拆解。

场景操作包括：

- 纹样：四方连续、修改画风、提取元素、生成配色组。
- 写真：重打光、换服装、换图案、换模特、换姿势、换场景。
- 线稿：真实渲染、补全结构、生成面料表现、生成商品图。
- 商品图：转线稿、生成电商主图、细节图、场景图、宣传海报。
- 随手拍：校正透视、清理背景、棚拍化、识别单品、生成搭配。
- 面料：无缝化、材质增强、颜色替换、应用到服装、生成近景细节。

单选时显示通用能力与所有命中标签的专属能力。多选时默认显示所有选中图片均可执行的能力交集。“全部”视图展示完整能力，并标明适用图片数量。无法执行的图片不会被静默跳过，用户需要确认执行范围。

每个图片操作必须声明：

- 适用条件，使用可组合 predicate，而不是单一标签数组。
- 输入对象和 `applicableImageIds`。
- 输出数量、尺寸和默认落点。
- 是否生成派生节点；首轮所有生成或编辑类操作均为非破坏性。
- 来源关系、Mock 参数、取消、失败、部分成功、重试和撤销语义。

派生结果默认放在来源图右侧，并用可选来源连线表示。批量操作在执行前显示适用数量；确认前 Mock API 调用次数必须为零。部分成功时成功结果保留，失败项可单独重试。

## 9. 画布选择与 Agent 上下文

画布支持点击、框选、多选、画笔圈选、划线批注和区域截图。

选择完成后显示上下文工具条，提供：

- 添加到 Agent 参考图。
- 生成带批注截图并添加到 Agent。
- 对齐、等距分布、分组和调整图层。
- 批量执行图片操作。
- 仅让 Agent 分析选区，不产生新内容。

Agent 输入框顶部显示可横向滚动的参考图托盘。每张参考图包含缩略图、编号、短名称、来源和移除操作。

输入 `@` 打开图片选择器，支持以下引用形式：

- `@图1`
- `@红色连衣裙正面`
- `@当前选区`
- `@刚才圈选的袖口`
- `@图1的版型`
- `@图3的纹样`

引用时，输入框和画布同步高亮对应图片或局部区域。消息保存稳定对象 ID，不仅保存显示名称，因此重命名后引用仍然有效。

项目内的画布与历史记录共享，但每个会话拥有独立上下文。将对象加入另一会话时必须显式执行“添加到当前会话”。Agent 在意图不明确时优先提出一至三个澄清选项；需要比较视觉方向时才向画布生成候选结果。

实体归属固定为：

- 设备本地拥有多个项目索引。
- 每个项目拥有一张画布、创作历史、生成器和项目资产引用。
- 每个项目拥有多个会话。
- 每个会话拥有消息、参考托盘和发送时的显式引用集合。
- Generator 属于项目；发起它的会话 ID 只作为来源记录，切换会话不会隐藏画布结果。

会话必须支持新建、重命名、切换和删除，并在刷新后恢复。删除含未完成任务的会话不会取消项目级 Generator，但会移除该会话的消息上下文。

引用分为：

- `live-object`：跟随当前画布对象，重命名后继续解析。
- `frozen-snapshot`：保存发送时图片或对象属性，不随来源修改。
- `region-snapshot`：保存来源对象 ID、画布区域和持久化批注截图。

发送前，Composer 显示最终引用清单。消息发送后引用类型不可静默改变。删除来源对象时，如存在由该对象派生的 `live-object`、`frozen-snapshot` 或 `region-snapshot`，必须先显示引用与快照数量，并要求用户二选一，不得预选：

1. **保留冻结快照**：把 `live-object` 转为 `frozen-snapshot`，保留已有冻结/区域快照，并在消息中标记“来源已删除”。
2. **级联删除引用**：从参考托盘和后续 Agent payload 中移除相关引用；历史消息只保留不含图片内容的“引用已删除”占位，并删除无其他可达引用的快照 Blob。

取消对话框不得改变对象、消息、引用或资产。清空项目始终级联删除对象、会话、快照和无其他可达引用的资产 Blob。

构建 Agent Mock payload 时只允许包含当前会话显式引用的对象和属性；未引用画布对象出现数必须为零。中文 `@` 提及使用结构化 mention token，保存 token range、reference ID、可选属性 suffix 和消歧结果，并正确处理 IME composition。

## 10. 图库与历史记录

原“资产库”改名为“历史记录”。工作台同时提供以下图库：

- 模特。
- 服装。
- 鞋履。
- 箱包。
- 配饰。
- 面料。
- 纹样。

每类图库都区分用户私有图库与公共图库。用户可以把上传、生成或处理后的结果保存到自己的图库，也可以选用公共图库内容作为参考。

信息架构明确区分：

- **撤销/重做**：画布命令历史，不作为资产列表展示。
- **创作历史**：项目级上传、生成、编辑和导出事件，可把结果重新插入画布。
- **我的图库**：设备本地可跨项目复用的用户资产。
- **公共图库**：随原型打包的只读演示素材。

公共图库每个素材包含来源、作者或提供方、授权状态、使用范围和“仅演示/可导出”标记。模特素材还需包含肖像授权说明。派生结果保留来源链；缺少授权信息的素材不得标记为可商用。

原型中的“私有”只代表当前浏览器配置文件本地可见。`UserProjectPanel` 常驻显示“仅存于此浏览器”标识，并可展开共享设备风险说明。项目菜单提供“删除当前项目”，数据管理对话框提供“清除全部本地数据”。确认界面必须列出将删除的项目、会话、快照、我的图库资产和本地备份范围；取消不得产生写操作。清除全部数据成功后创建一个新的空白项目并显示完成反馈。

### 10.1 项目操作

`UserProjectPanel` 支持新建、重命名、切换和删除项目：

- 新建项目创建空白 `ProjectDocument`，使用当前设备的全局布局；只有项目已保存覆盖配置时才使用项目布局。
- 重命名要求去除首尾空格后名称非空；重名允许，但项目列表同时显示稳定项目短编号或最近修改时间以便区分。
- 切换项目前必须 flush 当前项目。保存失败时保持当前项目不变并提供重试，不得静默切换或丢弃修改。
- 删除项目必须确认项目名称和删除范围，取消不得产生写操作。确认后取消该项目未完成的 Mock 任务并忽略迟到事件，再删除项目文档、会话、创作历史和项目快照；仍被“我的图库”或其他项目引用的资产不得删除。
- 删除当前项目后切换到最近使用的剩余项目；若没有剩余项目，则创建并打开一个新的空白项目。

## 11. 伴随表单式生成器节点

生成器由两个绑定部分组成：

- Konva 生成占位节点：显示生成类型、输出尺寸、宽高比、空状态、进度和结果。
- React DOM 参数表单：显示参考图、选区、提示词、模型、比例、清晰度、技能、语音和提交操作。

交互规则：

- 表单默认位于节点下方，缩放和平移时同步跟随。
- 拖动节点时，两部分整体移动并参与网格、对象边缘与中心线吸附。
- 表单保持固定 UI 尺度；宽度依据节点的屏幕包围盒计算并限制在 320–560 CSS px，不直接使用画布单位。
- 可视空间不足时，表单自动翻转至上方或左右侧，不得超出可视区域。
- 表单可以收起为短胶囊，也可以解除伴随成为独立浮动面板。
- 参数下拉菜单与选择器使用 DOM 浮层，不受 Konva 裁切或画布缩放影响。
- 点击画布空白收起临时参数层，但保留已输入内容。
- 复制生成器时复制参数与参考关系，不自动重复执行生成。

状态流转为：

`empty → configured → queued → generating → completed`

并支持 `paused`、`cancelled`、`failed`、`retrying` 和 `partial`。

生成过程中显示轻量动态反馈与阶段文字。成功后结果替换占位图，同时保留原始参数以便重新生成。失败后保留提示词、参考图和参数。

状态与可用操作：

- `empty/configured`：提交或删除。
- `queued`：取消。
- `generating`：暂停或取消。
- `paused`：继续或取消。
- `partial`：接受已有结果、补生成缺失项或全部重试。
- `failed`：重试、修改参数或删除。
- `completed`：重新生成、复制参数、保存图库或导出。
- `cancelled`：重新提交或删除。

每次运行都有稳定 `requestId`。取消、重试、切换会话、删除节点或组件卸载后，旧请求的迟到事件不得覆盖当前状态。刷新后排队中或生成中的 Mock 任务恢复为 `paused`，由用户决定继续或取消。

在 0.1× 缩放下表单可退化为连线胶囊；在 1× 与 4× 下保持 320–560px 宽度并限制在 VisualViewport 内，不能因翻转阈值抖动。

首轮实现图片生成器，并为视频、纹样和模特换装生成器预留基于配置的扩展接口。

## 12. Mock 数据与状态

Mock 服务模拟：

- 网络延迟。
- 正常结果。
- 空数据。
- 图片识别中。
- 生成中。
- 失败和重试。
- 部分结果。

图片识别返回固定 Mock 标签，前端使用真实规则计算操作能力交集。Mock 语音按钮只模拟转写，不申请麦克风权限。

本地持久化分为：

- localStorage：版本号、项目索引、轻量文档元数据、会话元数据和设备布局 profile。
- IndexedDB：上传图片、缩略图、生成结果和批注快照 Blob。

保存过程显示“保存中、已保存、保存失败”。250ms 防抖后保存，并在 `visibilitychange/pagehide` 时 flush。迁移或解析失败时先保留损坏数据备份，不能静默覆盖原 key；配额不足不得破坏最后一份有效文档。undo/redo 历史首轮不跨刷新恢复。

资产回收采用可达性扫描，不使用手工引用计数作为事实来源。可达集合必须覆盖所有项目文档、当前会话与消息快照、创作历史、我的图库，以及内存中 undo/redo 的 `past/present/future`。Blob 先写入再提交元数据；删除先成功提交元数据，再基于“已持久化可达集合 ∪ 内存历史可达集合”回收。undo 后只要 redo 仍引用资产就不得删除；仅在 redo 截断或历史淘汰且没有其他可达引用后回收。

Mock 接口与 UI 状态解耦。未来接入真实后端时保持接口契约，避免重写组件。

## 13. 错误与恢复

- 图片识别失败时在图片节点上提供重试。
- 生成失败时保留输入、引用和参数。
- 面板位置异常或移出视口时自动校正，并提供恢复默认布局。
- 引用对象被删除后，严格执行 §9 的用户选择：保留冻结快照并标记来源已删除，或级联删除引用与无其他可达引用的快照 Blob；不得自动保留快照。
- 不使用阻断整个画布的全屏错误页；错误尽量在原位置反馈。
- 识别、生成和导出均支持取消；取消后迟到的成功事件不得改变已取消状态。
- 资产读取失败时显示缺失占位与修复/删除操作，不以演示 fixture 静默替换用户内容。

## 14. 首轮原型范围

首轮包含：

- 无限画布缩放、平移、框选、多选、基础对齐、图片、文字和矢量笔迹节点。
- 本地图片导入、Mock 识别、标签纠错、非破坏性 Mock 图片操作和派生结果。
- 四个可拖动、吸附、悬浮、收起和恢复布局的主面板。
- 可展开工具栏和画笔二级浮层。
- 选择、手形、画笔、套索/批注、文字和上传工具的可用核心行为。
- Agent 会话 CRUD、参考图托盘、结构化 `@` 引用、提示词扩写、技能选择和 Mock 澄清流程。
- 历史记录与七类服装专业图库。
- 图片多标签识别结果与上下文操作菜单。
- 图片生成器占位节点与伴随参数表单。
- 小地图视口指示与点击导航、网格/吸附开关和尺寸、缩放控制、图层管理与快捷键帮助。
- 选区 PNG 和作品区域 PNG 导出。
- 桌面和 iPad 横屏响应式布局。
- 浅色主题和完整主题 Token 架构。

首轮不包含：

- 真实登录与账号服务。
- 真实 AI、图片或视频生成。
- 实时多人协作。
- 完整主页和公开灵感库体验。
- 工具栏不显示公开灵感库入口；该入口留到主页与发现体验阶段。
- 音频和视频画布节点及真实语音录制；首轮仅模拟语音转写按钮。
- Apple Pencil 高级压感笔刷调校。
- 深色与高对比度主题的完整视觉实现。

## 15. 验证标准

`CR-*` 是需求分组 ID，不直接作为最小验收单位。§1–14 的每条规范性要求必须映射到 §16 中至少一个原子验收条款，格式为 `CR-AREA-NNN.ANN`。每个原子条款只验证一个可观察结果和一个阈值；可用表驱动方式覆盖同一不变量的等价输入，但不能把创建、移动、复制、删除等不同结果压在同一条款中。实施前写明任务、自动测试或有理由的人工步骤、环境、阈值、证据路径和门禁等级；不得使用未量化的“正确、流畅、完整、无明显问题”。规格与验收矩阵的父需求和原子条款集合都必须 100% 一致。

自动验收：

- Vitest 覆盖纯函数、reducer、状态机和 DOM 组件；全局 branches/functions/lines/statements 均不低于 80%，coordinates、snapping、panel-layout、references、persistence、generator-state 的 per-file branch coverage 不低于 90%，低于阈值必须以非零退出码失败。
- Playwright 在 Chromium、Firefox 和 WebKit 运行黄金路径，要求 0 未捕获异常、0 console error、0 失败断言。
- 固定数据和自托管字体下保存 1280×720、1440×900、1920×1080、1194×834、1366×1024 截图。像素基线只在固定 `chromium-visual` CI project 使用；Firefox 与 WebKit 做功能和几何断言。首次候选截图必须由产品负责人签核后才能成为基线，manifest 记录 fixture、字体、浏览器/OS/container、viewport、动态 mask、截图 SHA-256 和加密签名的批准回执；明文姓名不构成批准。任一基线变更缺少有效新签名时失败。每张截图 pixel diff 不高于 0.2%。
- axe 在默认、菜单展开、错误、生成中和完成状态下按 `wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`wcag22a`、`wcag22aa` tags 检查，所有 violation 为 0，不按 impact 过滤且不得关闭 `color-contrast`。Canvas DOM mirror 接受同一检查。
- WCAG 2.2 AA：实际 computed 正文对比度至少 4.5:1；大字、非文本控件边界和焦点指示至少 3:1。
- 所有可交互控件位于 VisualViewport 内，无意外水平滚动或关键面板完全重叠。
- DOM/Konva 锚点在 0.1×、1×、4×、旋转、滚动和 resize 下误差不超过 2 CSS px。

性能验收使用 production build、固定随机种子，以及 1000 节点、500 条笔迹、50 个引用和 20 个生成器的固定 fixture。仓库同时保存一条 60 秒确定性动作 trace，逐项定义时间戳、动作类型、对象 ID、起止坐标/缩放、持续时间和等待点；桌面与 iPad 性能运行都由同一 benchmark runner 重放该 trace，人工 Pencil 手势另行验收。修改 trace 必须更换 fixture/version hash 并重新签核。Task 0 必须先把桌面 CPU、RAM、GPU、OS、刷新率、电源模式和 Chromium build 写入验收矩阵；硬件或浏览器改变时重新签核基线。

桌面执行 2 次预热和 5 次独立 60 秒测量。FPS 由 rAF 采样；输入延迟定义为 pointer event 到相应视觉提交后首个 rAF；内存使用 Chromium CDP `JSHeapUsedSize`，前后均请求一次 GC；TTI 使用应用 ready performance mark。五次结果的中位数必须满足：

- 桌面平移/缩放中位帧率不低于 55 FPS。
- 输入延迟 p95 低于 100ms。
- 60 秒内无超过 20% 的持续内存增长。
- 首屏可交互时间低于 2 秒。

iPad 使用 Safari Web Inspector 与应用内 rAF/Event Timing 日志，执行 2 次预热和 3 次独立 60 秒测量；三次中位 FPS 不低于 45，输入延迟 p95 低于 150ms。iPad 保存内存和 TTI 趋势，但不把跨工具不可比的绝对值作为硬门禁。

真实设备验收使用 iPad Pro 11-inch（屏幕 CSS 尺寸 1194×834）和 iPad Pro 12.9-inch（屏幕 CSS 尺寸 1366×1024）两类设备、Safari 与兼容 Apple Pencil。屏幕 CSS 尺寸不等于动态工具栏后的 VisualViewport；每次测试必须记录具体型号、iPadOS/Safari build、Pencil 型号、显示缩放、浏览器工具栏状态和实际 `visualViewport`。双指缩放中心漂移不超过 2 CSS px；双指平移不触发绘制；Pencil 只在画笔或套索/批注工具下绘制；拖动面板抓手不移动画布。每项连续执行 20 次，全部不得出现意外页面滚动、浏览器缩放、错误工具绘制或 stuck pointer。每个 Pencil 绘制序列的日志包含 `pointerType === "pen"`、至少一个 `pressure > 0` 事件以及有限值 `tiltX/tiltY`。验收保留视频与事件日志；任一目标设备不可用时不得标记实机条款通过。

仅键盘必须能够切换工具、使用菜单、选择图层树对象、删除和微移对象、移动/吸附面板、调整 Agent 宽度、恢复布局、提交生成和重试。异步状态使用 `aria-live`，关闭浮层后焦点回到调用者。

### 15.1 用户研究验收

最终产品验证前邀请至少 5 名符合首轮主角色的独立服装设计师。参与者在未接受产品培训的情况下完成两条黄金路径；主持人只可朗读任务，不得指出控件位置或解释 Agent 上下文规则。

通过条件：

- 至少 4/5 参与者独立完成每条黄金路径，且无素材丢失或误覆盖原图。
- 至少 4/5 参与者在任务后准确说明：“Agent 只读取当前会话中显式加入的引用，不会自动读取整张画布。”
- 至少 4/5 参与者在选中服装图片后 30 秒内找到“换面料”或“换纹样”，并在执行前正确判断适用图片数量。
- 至少 4/5 参与者能区分“创作历史”“我的图库”“公共图库”和“撤销/重做”。
- 任一参与者误认为 Mock 识别/生成是真实 AI，或误认为素材已上传网络时，认知真实性条款不得通过。

证据只保存匿名参与者编号、完成结果、耗时、关键错误、主持人介入次数和结论，不保存参与者素材或身份信息。阈值未达到时 `CR-PROD-001` 保持失败，记录修订并复测。

### 15.2 门禁与豁免

每个原子条款在 Task 0 标为 `release` 或 `waivable`，实施开始后不得降级。两条黄金路径、数据不丢失、未引用对象隔离、三浏览器黄金路径、WCAG、实机 iPad/Pencil 和性能阈值都是 `release`，不可豁免。只有预先标记为 `waivable` 的非关键条款可以临时豁免，且必须记录条款 ID、实测值、用户影响、原因、产品与技术负责人加密双签、跟踪 issue、证据和不超过 14 天的到期日。Task 0 基线 commit 与允许签名公钥由受保护 CI 环境提供，不能由实现提交自行替换；明文姓名无效。过期、签名或字段不全的豁免，以及任何 `planned`/`failed` release 条款，都阻断交付。
