# Loomoon 新建项目与 Agent 会话设计

日期：2026-07-27

## 1. 目标

让首页、项目页、全局左侧“＋”和 Canvas 项目菜单中的所有新建入口遵循同一套项目生命周期，并确保每个项目拥有独立的 Canvas 状态和 Agent 对话。

本阶段修复以下现状：

- Canvas 内创建项目后 URL 仍指向旧项目。
- 新项目沿用旧项目的 `agentSession`、消息、运行状态或 Agent 组件内部的乐观消息。
- Canvas 内直接切换项目时，浏览器前进、后退和刷新不能恢复当前项目。
- 空项目会被前端临时填入六个演示图片节点，不是真正的空白画布。
- 首页提示词必须等 Agent 请求完成后才进入 Canvas；失败时用户不知道项目是否已经创建。
- 全局“新建项目”和项目页“新建项目”目前只返回首页，没有真正创建项目。

## 2. 已确认的产品规则

1. Canvas 或项目页创建项目时，进入真正的空白画布，并初始化一条独立的空白 Agent 会话。
2. 首页输入提示词、快捷提示词或灵感同款创建项目时，先创建并进入新项目，再把提示词作为该项目 Agent 会话的第一条用户消息发送。
3. 新项目绝不继承旧项目的对话、运行状态、选中对象、输入内容、撤销记录或临时工具状态。
4. Agent 首条消息发送失败时，项目仍然保留；失败消息继续显示在新项目对话中，并允许用户重试。
5. 不改变现有视觉语言和邮箱密码登录方式；桌面端和移动端使用同一行为规则。

## 3. 入口行为

### 3.1 空白项目入口

以下入口创建空白项目：

- 全局左侧导航顶部“＋”。
- 登录首页“最近项目”中的“新建项目”卡片。
- 项目列表页右上角“新建项目”。
- Canvas 项目切换菜单中的“＋ 新建”。

全局、首页和项目页入口使用默认名称“未命名项目”，创建成功后直接进入 Canvas。Canvas 内入口保留现有名称输入模态层，提交成功后进入新项目。

创建请求进行中时，触发入口保持禁用，避免连点生成多个项目。创建失败时停留在原页面并显示可理解的错误，不改变当前项目。

### 3.2 带提示词的项目入口

以下入口创建项目并发送第一条消息：

- 首页 Agent 输入框。
- 首页快捷提示词。
- 灵感详情中的“做同款”。
- 未登录时提交提示词，登录成功后恢复的同一意图。

流程为：创建项目 → 保存一次性首条消息交接 → 更新项目列表 → 跳转项目 URL → 加载项目和独立会话 → 在 Agent 对话中乐观显示并发送首条消息。

灵感同款继续在首条消息中附带案例标题及构图、材质、配色分析要求，不改变现有提示词语义。

## 4. 项目身份与路由

Canvas 的唯一项目身份来自 `/canvas?projectId=<id>`。`AppShell` 把路由中的 `projectId` 显式传给 Canvas 工作区，Canvas 不再只在首次挂载时读取 `window.location.search`。

创建或切换项目必须先更新 AppShell 路由。浏览器刷新、前进和后退随后都能重新加载对应项目。Canvas 项目菜单不再绕过路由直接调用局部 `loadProject`。

异步加载使用递增请求序号或等价的取消标记。用户快速切换项目时，旧请求不得覆盖较新的项目状态。

## 5. 项目级状态边界

开始加载另一个项目时，先同步清除以下状态，再请求新项目数据：

- `project`、`nodes`、`selection`。
- `pending`、`agentSession`、`agentMessages`、`agentRun`。
- Agent 首条消息交接状态和输入草稿。
- `history`、`future`、区域编辑目标和生成历史面板。
- 框选、绘制、形状草稿、工具弹层和图层面板。
- 保存定时器、生成器临时定时器及当前项目的 SSE 连接。

相机恢复为 Canvas 默认缩放与位置，工具恢复为选择工具，右侧 Agent 面板的开关状态可以保留，因为它属于用户布局偏好，不属于项目数据。

项目加载完成后：

- `nodes` 只来自 `project.canvas.nodes` 并执行已有节点标准化。
- 空数组保持空数组，不创建或选中演示节点。
- 调用现有 `createAgentSession(projectId)`；服务端保持同项目幂等、跨项目隔离。
- 加载该会话的持久化时间线和活动运行。
- Agent 侧栏以 `sessionId` 或 `projectId` 作为 React `key`，确保内部乐观消息不会跨项目存活。

## 6. 首页首条消息交接

新增 `project-launch-intent.ts`，使用当前标签页的 `sessionStorage` 保存一次性消息：

```ts
export interface ProjectLaunchIntent {
  id: string;
  projectId: string;
  prompt: string;
  createdAt: string;
}
```

采用 `sessionStorage` 的理由：

- 路由切换或 Canvas 组件重新挂载时不会丢失。
- 不把完整提示词暴露在 URL 或浏览器历史中。
- 不跨浏览器标签页错误复用。
- 可以按 `projectId` 精确消费一次。

Canvas 只有在项目和 Agent 会话均加载成功后才消费对应项目的交接消息。损坏、空白或项目 ID 不匹配的数据会被忽略；其他项目的交接数据不得被提前删除。

## 7. Agent 首条消息与重试

`AgentSidebar` 增加可选的外部首条消息输入。它使用现有 `optimisticUserMessage`、`mergeAgentMessages` 和失败重试逻辑发送，因此首页提示词在请求开始时就出现在新项目对话中。

首条消息只自动提交一次：

- 开始提交后立即标记为已经接管，避免 React StrictMode 或重复渲染再次发送。
- 成功后由服务端持久化时间线替换乐观消息，不重复显示。
- 失败后消息标记为 `failed`，内容和选择快照保留，用户点击现有重试入口重新发送。
- 项目切换时侧栏卸载；旧项目的失败消息不会出现在新项目。

## 8. 服务端边界

当前服务端已经满足本阶段的关键规则：

- `ProjectRegistry.create` 为用户创建独立项目文件。
- `AgentCoordinator.createSession(userId, projectId)` 对同一项目返回最近会话，对不同项目创建不同会话。
- 会话、消息和运行均包含 `userId` 与 `projectId`。

本阶段不新增复合创建接口，也不让项目创建等待 Agent 完成。增加回归测试证明同用户的两个项目不会共享会话或消息。

## 9. 错误与并发

- 项目创建失败：不导航、不清空当前工作区。
- 项目加载失败：保留目标 URL，显示错误和可刷新恢复的空工作区，不回退到旧项目。
- Agent 会话加载失败：项目与空白画布仍可见，Agent 区显示错误。
- 首页首条消息失败：项目保留，消息显示失败状态并可重试。
- 快速切换项目：仅最后一次加载结果可以写入界面。
- Canvas 自动保存不得把旧项目节点写入新项目；切换前清除保存定时器并暂停保存，完成新项目水合后再启用。

## 10. 验收标准

1. 从四个空白入口分别创建项目，都会进入包含新 `projectId` 的 Canvas URL。
2. 新项目 Canvas 没有演示图片、没有选择对象，撤销和重做均为空。
3. 新项目 Agent 对话为空，发送消息后只出现在当前项目。
4. 从首页提交提示词后先进入新项目，提示词立即作为第一条用户消息显示。
5. 首条消息失败时显示失败与重试，刷新后项目仍存在。
6. 在项目 A 产生对话后新建项目 B，B 不显示 A 的持久化或乐观消息；切回 A 后 A 的对话仍在。
7. Canvas 项目菜单切换项目时 URL 同步变化；刷新、前进和后退加载正确项目。
8. 连续快速切换 A/B/A，最终界面、Canvas、Agent 会话和 URL 都属于最后一个 A。
9. 桌面端和移动端入口均可用，创建中不能重复提交。
10. Web、Agent UI、API 测试、全仓类型检查与构建通过。
