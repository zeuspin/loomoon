# Design Agent 结果流与方向选择设计

## 背景

当前 Agent 侧栏将项目消息、待确认计划、确认记录和全部图片生成历史分别聚合后顺序渲染。这造成三个问题：

1. 对话与结构化操作没有按发生顺序组织；
2. 历史图片任务持续堆积在侧栏底部；
3. 创意方向只作为静态内容展示，用户无法表达选择。

## 设计原则

- 画布是所有生成图片的唯一展示区域。
- 对话侧栏只呈现沟通、决策、确认和紧凑任务状态。
- 不在对话侧栏展示生成图片缩略图、完整 Prompt 或历史图片列表。
- 结构化卡片必须与触发它的对话保持上下文关联。
- 默认支持两个方向各生成两张，也支持选择单一方向生成四张。

## 对话信息结构

侧栏按以下结构展示：

1. 用户消息；
2. Agent 文本回复；
3. 当前创意计划卡；
4. 当前确认卡；
5. 当前任务进度；
6. 完成说明。

已完成的图片任务不再逐项渲染。任务完成后仅显示类似“4 张图片已放入画布”的状态说明。

同一时间只展示当前可操作的计划、确认和执行状态。旧计划、已消费确认以及历史生成任务不会继续占据对话主流。

## 创意方向选择

每个方向使用可点击的选择卡：

- 卡片展示标题、风格、构图和色板；
- 选中态必须具备明确的视觉反馈和无障碍状态；
- 用户可以选择一个方向；
- 未选择方向时，主操作为“两个方向各生成 2 张”；
- 选择方向后，主操作变为“采用此方向并生成 4 张”；
- 用户可以取消选择并恢复双方向生成。

选择方向本身不调用图片 Provider。只有用户点击最终生成操作并通过确认门后，才创建付费任务。

## 数据与交互

前端维护当前计划的方向选择状态，选择值为 `directionId | undefined`。

确认请求需要携带：

- 当前计划 ID；
- 选中的方向 ID，或双方向模式；
- 任务数量；
- 当前 Run 和 PendingAction；
- 规范化输入哈希。

后端必须在消费确认时重新验证方向属于当前计划。方向或任务模式发生变化时，旧 PendingAction 失效并重新创建确认，不能复用原输入哈希。

本次界面修正首先移除对 `generationHistory` 的逐项侧栏映射，并提供紧凑的当前任务摘要。图片节点及其状态仍由画布和项目 SSE 更新。

## 错误与恢复

- 单项图片失败只在紧凑状态中显示成功数和失败数；
- 用户通过画布选择失败节点进行重试；
- 刷新后从当前计划、PendingAction 和 Run 恢复方向选择与确认状态；
- 不存在活动 Run 时，不显示历史确认或历史任务卡；
- 方向选择与确认输入不一致时，要求用户重新确认。

## 验收标准

- Design Agent 侧栏不出现任何生成图片缩略图。
- Design Agent 侧栏不逐项展示历史图片 Prompt。
- 历史项目无论有多少 GenerationRecord，侧栏高度都不会因此无限增长。
- 两个创意方向均可点击选择，并具有清晰选中态。
- 未选择方向时可生成两个方向各两张。
- 选择一个方向时可生成该方向四张。
- 方向选择不会直接产生图片费用。
- 生成完成后图片全部出现在画布，侧栏只显示简短完成状态。
- 用户消息、Agent 回复和结构化状态保持上下文顺序。
- 刷新后不会重新展示已消费确认和历史生成列表。
